# CPU-AXIL-06：访存异常与机器中断竞争

状态：限定 RTL 定向验证 PASS，待两名非作者审核；不是完整异常优先级、综合网表或实物验收。

## 输入与范围

- 沿用 CSR 修复后的真实 CPU，SHA-256 `d0e23f3c4de105dd2c547f41c4bc5f81dd89b3d7d6dba34db8b3062eea701a25`。
- CPU 生成器、CPU RTL、AXIL 桥和综合 SoC 均未修改；新增独立固件、测试台、检查器和运行脚本。
- 复用独立 `cancel_target.sv`，错误写不修改其测试内存。这是目标模型政策，不承诺真实外设错误写可以回滚。
- 通过 CPU 的 softwareInterrupt/timerInterrupt/externalInterrupt 引脚施加持续电平；不用 force 修改 CPU 内部状态。不是原 SoC 的按键同步、计时器或软件中断寄存器的集成验证。
- 异常为 LW cause 5、SW cause 7，访问地址 `0x10000000`；这些地址仅供离线夹具使用。

## 实际执行

```bash
export AXIL_CPU_BUILD=/your/legal/axil-cpu-v5
bash validation/axil/run_competition.sh
```

脚本固定 CPU 哈希，编译 12 份固件，保存 ELF、反汇编、符号表、逐周期轨迹、固件读取真实 CSR 后写出的记录和输入哈希。Python 预期独立于 CPU RTL：依据访存类型确定 cause，依据固件符号确定精确故障 PC，不把 DUT 的 trap/done 当作正确性结论。

矩阵：2 种 LW/SW × 3 种 MSI/MTI/MEI × 2 种 mie 开启/屏蔽 × 3 个 IRQ 到达窗口 × 2 种 AXIL 错误码 SLVERR/DECERR × 2 档目标延迟（3/17 周期）= **144 配置**；每配置复位启动两次，共 **288 次启动、432 次处理程序进入、4752 条固件结果记录**。

三个窗口从真实握手/退休事件触发，检查器还核对实际周期关系：

1. 已接受故障访存、错误响应返回前，中断先变 pending；桥额外扣住响应至请求后至少 12 周期。
2. IRQ 与 CPU 消费 `rsp_valid/error` 的同一个上升沿有效；不声称与内部 trap 信号同沿。
3. 同步异常处理程序首条指令退休后才断言 IRQ，形成迟到对照。

延迟 3/17 是目标模型参数，不冒称端到端响应延迟。测试台在下降沿调整输入，避免与 CPU 上升沿采样竞争。

## 验收结果

- 全部 144 配置通过；被接受且仍在途的故障 LW/SW 先报告同步异常。该结论限定于本配置和这三种刺激时序，不宣称所有 RISC-V 实现都必须对任意异步到达给出相同次序。
- `mepc` 精确等于故障指令；`mtval` 等于故障地址；机器态入口 MIE=0、MPIE=1、MPP=M。
- 故障指令未成功退休，紧随其后的年轻标记指令未退休/修改寄存器；错误 load 目的寄存器保持哨兵，较老寄存器值保持。
- 异常返回跳过故障及年轻标记指令。未屏蔽 IRQ 不丢失，在返回后恰好处理一次，IRQ `mtval=0`，恢复 PC 位于明确的恢复循环区间；应答后不重复进入。
- mie 屏蔽时同步异常仍成立，IRQ 保持 pending，但在此次有限观察窗口内不进入 IRQ handler。
- 每次启动故障命令恰好接受一次、错误响应恰好一次，错误目标内存不变，固件完成计数正确。

检查器负向：12 种固件记录突变和 8 种轨迹突变均以指定原因拒绝，包括 cause/PC/mtval/mstatus、pending 丢失、寄存器污染、错误退休、响应丢失、目标写污染、应答与完成错误。

实际 RTL 负向：在本地副本中将桥的 `rsp_error` 压为 0，分别运行 LW/SW。两种变体首个 cause 均错误变成 MSI，检查器以 `FIRST_CAUSE` 拒绝；不把之后的固件超时当作唯一负向依据。正常 CPU、固件和预期均不变。

实际重跑既有基线：

- `run_soc.sh`：199 个独立结果 × 两次启动通过；预期突变被拒绝。
- `run_irq.sh`：16 种同时 pending 组合、四次启动、144 次处理通过；14 个记录突变和实际优先级反转变体被拒绝。
