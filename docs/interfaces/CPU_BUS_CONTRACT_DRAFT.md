## 1. 用人话说明

“总线收到了请求”不等于“数据已经写好”。CPU 必须等到写响应才能把该条写指令算作成功；DMA 必须等数据写完才能通知 CPU；取消任务后，旧 DMA 仍可能在写，缓冲不能立即给新任务使用。

## 3. CPU 写事务合同（建议批准内容）

生产者：CPU LSU；消费者：互连、RAM/DDR或MMIO目标；完成返回消费者：CPU退休/异常逻辑。

第一版采用单在途 store，暂不引入吞吐型写缓冲。每笔保存故障归属信息：指令PC、物理地址、数据、字节使能、访问宽度、事务标识和错误状态。具体信号命名/位宽待实现审查。

```text
检查地址/权限/对齐
  ├─拒绝 → 不发外部请求 → 对该指令报异常
  └─合法 → 持有请求 → 分别跟踪地址/数据被接受 → 等待对应响应
                                              ├─成功 → 允许该store成功退休
                                              └─错误 → 阻止成功退休 → 精确异常
```

1. AW、W 的握手独立记录，不假设同周期或固定先后；VALID 等待 READY 时地址/数据/控制保持不变，不重复发送已接受部分。
2. 只有匹配事务且实际握手的成功 B 响应，才满足写完成条件；仅看到 READY、W已入队或计数减零都不能替代。
3. 错误响应必须归属原 store；mepc 指向故障指令、mcause/mtval 与该访问对应。更年轻指令不得先产生不可撤回的架构或 MMIO 副作用。
4. store 发出前必须排除可导致它成为错误路径的更老分支/异常。请求一旦被接受不能假装撤回，需排空/隔离。精确异常不承诺撤销目标内部已经发生的部分写入；错误缓冲须标记无效，软件不得当作完整数据消费。
5. 单在途降低复杂度但不能靠延迟一个 ready 信号实现；需审查流水线保持、异常优先级、冲刷和退休位置。
6. 第一版 CPU 未对齐访问采用 trap；非法物理范围、跨区域或地址计算溢出必须在产生副作用前拒绝。burst、原子操作、跨页等未定义能力不默认为支持。
7. 无响应时超时先报故障并隔离资源；超时不是成功、不是已取消，也不能释放槽位接受可能混淆的下一笔事务。阈值以实际互连最大等待合同确定，现为 TBD。

## 4. MMIO、FENCE 与可见性

- MMIO 不可缓存、不可投机；每寄存器明确允许读写方向、宽度、字节使能、读副作用、清除方式及复位值，未定义组合拒绝。
- 共享 DDR 使用 uncached CPU 窗口；不得让相同物理页另有 cached 别名。CPU私有缓存区不发布给DMA。
- 顺序原语需有编译器和硬件两层定义。volatile 不能替代桥接排空；FENCE 不自动清理/失效 Cache，也不证明 DMA 已完成。
- 若未来启用写穿Cache，仍需等待写响应；Cache refill 与 DMA 并发要独立验证。没有写回策略时不得填写“脏行写回通过”。
- 不自创软件 flush API 或寄存器地址；先确定实现机制，再固定驱动调用、指令及验收方式。

## 5. 缓冲所有权和完成语义

```text
FREE → CPU_PREPARE → DEVICE_OWNED → COMPLETE → CPU_READ → FREE
                           └─取消/错误/复位 → QUARANTINE
QUARANTINE → 证明确已排空或隔离、清理状态 → FREE
```

状态名为草案概念，不是已实现寄存器编码。多个CPU/设备只读者须有引用计数；存在任何读者时不能授予写者；写者独占。只读共享的具体生命周期由任务管理器统一管理。

|事件|前置条件|必须保证|
|---|---|---|
|发布描述符|CPU独占缓冲，地址/长度/stride/尾部byte-enable验证通过|数据与描述符先完成必要写响应和排序，再发布ownership/doorbell；设备不能看到半初始化描述符|
|设备开始|描述符版本与job/epoch/generation匹配，范围合法|设备取得授权范围，不得访问CPU私有区；检查地址加长度溢出、末尾beat越界|
|设备完成|相关读完成，全部写的成功响应完成，状态可见|最后发布完成事件；错误单独发布，绝不能伪装正常完成|
|CPU获取|完成事件的身份三元组与当前任务一致，执行规定获取顺序|只读取完整有效数据；重复完成不重复释放或执行动作|
|取消/复位|停止发布新工作，冻结相关所有权|旧在途写可达目标时缓冲留在QUARANTINE；仅丢弃旧IRQ或加generation不够|
|重新分配|确认互连/设备排空，或硬件隔离使旧请求不可能再触达该区|清理旧状态、重新授权；身份计数回绕前执行排空，不能碰撞旧任务|

缓冲64B起始对齐、Cache行32B是源方案建议，不是批准参数。物理DDR大小、用户接口位宽、频率、burst上限、缓存边界、描述符字段位宽、寄存器图均TBD。对齐起始地址不能证明stride和每个子行访问都对齐。

时钟与复位：CPU、DDR用户域、各DMA域须分别记录时钟来源和复位作用范围。跨域完成/取消采用经验证的握手或FIFO；仅复位CPU不能默认清掉DDR控制器中的写。全局复位也须依据控制器文档确认在途事务行为。

## 6. 独立验收向量（设计，以下均 NOT_RUN）

需独立总线目标/记分板提供请求接受、真实响应、内存变化、退休/异常和所有权时间线；不得用DUT自己的“done”推导正确预期。

|ID|输入/故障注入|独立判据|
|---|---|---|
|BUS-01|单笔合法写，分离AW/W握手，延迟B|响应前不退休，成功响应后恰好一次退休且内容正确|
|BUS-02|AW先/W先/同周期；各通道长背压|保持有效负载，无重复接受、无丢失，解除后进展|
|BUS-03|写接受后延迟返回错误，紧跟一笔有副作用MMIO|故障PC/地址准确，无成功退休，年轻副作用未发生|
|BUS-04|更老分支冲刷年轻store|错误路径不得产生外部写|
|BUS-05|非法/只读区域、未对齐、末地址溢出|拒绝且无目标副作用；异常信息可核对|
|BUS-06|分别在AW前、只收AW、只收W、等待B、B握手边缘复位|无僵尸新任务；已发事务排空或隔离，旧响应不得误配|
|BUS-07|永不返回响应|有界进入故障隔离，不以超时冒充完成；恢复策略单独验证|
|MEM-01|延迟描述符最后一笔写，尝试敲doorbell|消费者不能在发布条件满足前获取所有权|
|MEM-02|延迟DMA最后B/注入写错误|成功完成事件不得提前；错误数据不被消费|
|MEM-03|取消后旧DMA继续写，申请复用同缓冲|复用被拒绝直到排空/隔离；新任务数据不被旧写污染|
|MEM-04|过期/重复完成，身份计数临近回绕|旧事件不释放新缓冲、不重复消费；回绕前排空|
|MEM-05|DMA指向私有缓存区/红区或跨界尾beat|验证器拒绝，目标区域不变|
|MEM-06|两个读者未释放时申请写，读者逐个释放|最后一个读者释放前写者始终不能取得授权|
|MEM-07|专用测试配置保留非一致Cache旧行，DMA写底层内存|满足前提时观测旧值；生产配置另证实缓存别名被阻止，不把此负测用于生产|
|MEM-08|DMA持续负载与CPU并发，注入各域复位|CPU等待有约定上界；跨域无丢事件/旧完成混入；阈值待冻结|

当前已有测试只提供相关基础证据，不能将上述 NOT_RUN 改成 PASS：UART简单总线背压不是BUS-02的AXI验证；串口/除法复位不是BUS-06；片上RAM自检不是MEM系列。

## 7. 下一张可执行任务卡：CPU-WR-01（建议）

目标：在修改RTL前定位“哪一条store在何时被当成完成”，确认可实施的精确异常改造路径。

操作：固定上游commit和生成配置；审查DBusSimplePlugin的cmd发送、MEMORY_STORE、仲裁停顿、flush、exceptionPort；若选择DCache/AXI候选，另外审查桥接写计数与B错误回送，不假定与当前Simple实现相同。画出流水级/响应事件对应，标出必须保留的PC、地址和副作用屏障。

产出：源文件/行号证据表、两种接口路线比较、最小改造边界、BUS-01/03/06检查器设计。备选路线为局部CPU更换，不自动执行更换。

验收：能解释延迟B期间为什么不退休、错误如何回到原指令、年轻MMIO为何不发生、复位后旧事务如何处置；有尚未解决项就保留BLOCKED，不以纸面状态图宣称实现完成。

在接口草案获评审前，不直接把现有固件移植到新总线，也不让其他成员按猜测地址开始接线。候选方案、Cache规模、DMA描述符归属和超时上限集中提交团队评审；用户暂未安排分工，因此不代派负责人。
