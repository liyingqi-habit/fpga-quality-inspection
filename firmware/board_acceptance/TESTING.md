# BA-0.2 离线 RTL 验证入口

本入口不运行 PDS，不修改现有工程或 ROM，不生成位流，不操作板卡。
测试夹具是 `acceptance_tb.sv`，独立文字预期在 `check_uart.py`；预期不是从汇编字符串提取。

## 运行

在 Linux/WSL 仓库根目录，已有 RISC-V GCC/binutils、Python 3、Verilator
（支持 --binary/--timing）、C++ 构建工具和 Icarus 时：

```bash
export AXIL_CPU_BUILD=/path/to/legal/generated-rc1-cpu
export UART_FILE=/path/to/legal/mini_uart.v
bash firmware/board_acceptance/run_rtl.sh
```

CPU 与 UART 需匹配脚本中的固定 SHA256。第三方输入不随此目录分发。
输出建立在独立临时目录，保存编译记录、每例仿真日志、UART 原始文本、
固件 ROM 和前后输入摘要。默认运行下表全部场景、七种文字检查器反例、
一次串口解码字节变异反例，再用 Icarus 四态仿真运行释放窗口加速的正常场景并逐字节对比文本。
四态还运行 RAM 故障，以及将三条诊断 CSR 初始化改成 NOP 的测试 ROM：
前者必须有确定的 FAIL 10，后者必须因 UART 数据含 X 而被拒绝。

`CASES="1 12" FOUR_STATE=0` 可用于定向调试，但不能当成完整回归。
正常场景编号 0 存在时才运行文字变异和四态对照。
命令失败必须保留日志，不能仅筛选 PASS 行判通过。

## 场景及判据

|编号|刺激/注入|预期|
|---|---|---|
|0|真实原版 CPU/SoC/UART，按下并释放 KEY1|完整顺序文本，进入 idle，无 FAIL|
|1|首次 RAM 读回前翻转 word 0 的 bit 0|FAIL 10，无后续 PASS|
|2|屏蔽软件 IRQ 来源，推进计时器|FAIL 30|
|3|始终不按 KEY1，推进计时器|FAIL 41|
|4|按下 KEY1 后不释放，推进计时器|FAIL 42|
|5|UART 第一帧中复位|中断旧帧，重启后完整文本|
|6|等待 KEY1 时复位|旧启动停在按键阶段，新启动完整文本|
|7|强制 UART status busy|实际跑完轮询预算，静默失败、LED0=1，无成功文本|
|8|ECALL 处理器入口退休时复位|重新启动并完成全部流程|
|9|屏蔽 timer IRQ 来源，推进计时器|FAIL 31|
|10|启动前 KEY1 已按住，推进计时器|FAIL 40|
|11|释放阶段六次高低脉冲，然后稳定释放|脉冲期间不得提前进入按下阶段，之后完整通过|
|12|仅测试 ROM 将 ECALL 换成 EBREAK|FAIL E0，mcause=3，拒绝错误原因码|
|13|软件中断处理器入口退休时复位|旧软件 pending 随 SoC 复位清除，重启完整流程|

所有故障注入仅存在于夹具；未改变生产 CPU、桥、SoC、UART 或源固件。
case 12 修改的是一次仿真中的 ROM 数组，不改生成的 firmware.hex。

## 观察方式与限制

- 正常串口检查从顶层 TX 解码 8N1，234 时钟/bit，检查起始位和停止位；
  不读取 UART 写寄存器的值来冒充串口输出。
- PC 定位同时要求有效退休，不以可能被冲刷的流水线 PC 为执行证据。
  提示文字传完时 CPU 可能已进入等待，故记录阶段进入次数，避免漏掉一次性入口。
- 失败场景核对完整输出前缀、失败码和 CSR 文本格式；错误异常场景另检查 cause=3。
  其他失败行中的 CSR 是历史陷阱信息，不当成当前失败位置。
- 超时测试保留固件常数及控制流，仅在进入等待后将外设计时器推进
  810000100 ticks；不是实际等待 30 秒，也不覆盖所有回绕/临界周期组合。
  UART busy 用例不缩短循环预算。
- 四态正常场景用 `+FAST_RELEASE` 在两次释放等待期间分别推进 2700100 ticks，
  以减少空等开销；不是原速 100 ms 稳定窗口验证。Verilator 正常场景不加速这两个窗口。
- 四态复核运行正常场景、RAM 失败及撤销诊断初始化反例；完整故障矩阵由 Verilator 二态执行。
  不声称覆盖所有 X 传播、全部 RAM 故障、所有按键抖动或所有复位相位。
- 有限自检通过不等于完整 ISA、综合网表、PDS 时序或实物验收通过。
  物理串口电气、引脚、电压、时钟、按键和下载仍须独立人工核对。

实际通过情况以日期证据文档为准，不以本场景表代替运行记录。
