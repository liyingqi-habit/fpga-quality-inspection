# CPU-WR-02：独立写响应目标和检查器

状态：测试基础设施，**没有真实CPU/LSU/AXI桥接入**。关联 #6、#20、CPU_WR_01_AUDIT；不改变整机接口批准状态，不使BUS-01/03/06的CPU验收自动通过。

## 一条命令运行

依赖 Bash、Icarus Verilog/vvp、Python 3（标准库）、sha256sum。从仓库根：

```bash
bash validation/write_response/run.sh
```

不需要原CPU工程、PDS、厂家库、板卡、网络或Python第三方包。输出到唯一临时目录：run.log、输入哈希、sim、trace.csv。报告保留，不自动清理。SV驱动有2000周期超时，任何fatal、检查器异常或负向对照逃逸都会使脚本非零退出。

## 独立性与模块职责

- target.sv：验证用单槽、单beat、无ID的AXI-like写目标；AW/W分别接受，可注入通道背压、B延迟、SLVERR/DECERR式响应和永久无响应；B受阻时保持响应。它不是完整AXI从设备实现，也没有地址权限验证。
- driver_tb.sv：**合成驱动**，主动产生issue/retire/trap/释放事件；其正确时序是用来测试检查器的样本，不是LSU实现。模拟地址与PC只作测试标签，不是系统地址图。
- check_trace.py：独立读取原始周期事件，不读取目标内部done、不导入目标或驱动代码。按测试计划建立AW/W/B记分板，核对每次接受与完成、上下文、异常、年轻副作用、复位隔离及覆盖。
- test_mutations.py：在已观测轨迹中改坏事件，检查拒绝原因必须吻合；不是把预期随DUT一起修改。

目标内存采用固定字节掩码测试：初值11223344，WSTRB=0101；正常响应后期望11bb33xx，错误场景维持初值。驱动用独立常数核对内存结果。**错误不写内存是此模型政策，真实DDR/MMIO可能部分写后报错，不能据此承诺回滚。**

## 12个场景

|case|场景|
|---|---|
|0|AW先、W后，最短成功响应|
|1|W先、AW后，延迟7周期成功|
|2|AW/W同时呈现，4周期请求背压、延迟31周期成功|
|3 / 4|分别延迟返回响应代码2/3，期望原PC/地址的cause7异常，不退休|
|5|issue之后、任何通道接受之前复位，允许释放未发槽位|
|6 / 7|只接受AW / 只接受W时CPU复位，补齐剩余通道、排空旧B后才释放|
|8|等待B时CPU复位，旧B排空后才释放，不产生旧退休|
|9|CPU复位与B握手同周期，草案规定复位优先，不产生旧异常/退休|
|10|隔离/排空后重新使用槽位，成功完成新工作|
|11|CPU复位后目标永不响应，至少观察30周期，仍保持隔离、不释放|

除取消前未发及永不响应外，每个B均施加至少3周期背压。目标只接受全局bus_reset初始化，不连接cpu_reset，因此CPU复位不会自动抹去目标中已接受的半笔写。这里没有全局DDR复位或超时恢复测试。

检查器还验证复位落在指定阶段，而不是仅看到某个reset就算覆盖；每例恰好一次issue，正常/错误结果不能重复，等待请求和响应时载荷稳定，错误后/未完成前不得产生合成年轻副作用。

## 12个负向对照

提前退休、错误当成功、错误PC、错误地址、错误cause、年轻MMIO副作用、未排空即释放、旧事务退休、AW变更、W变更、B背压时变更、隔离槽位被新任务重用。各自必须抛出明确的违反规则代码；正常场景通过不足以证明检查器有效。

## 接入真实LSU前必须做的事

1. 评审并固定写响应和复位优先级合同；此模型选择“CPU局部复位后排空”，不是唯一合法策略。
2. 用真实LSU/桥替换合成驱动的总线发送；issue/retire/trap必须来自真实流水线观察口，禁止继续由测试台自行生成成功事件。
3. 从真实年轻MMIO请求获得副作用计数，不能把young固定为0；对错误store保留PC、地址、epoch映射。
4. checker目前绑定12例fixture；新随机场景须提供独立计划输入，不能直接宣称通用AXI协议检查器。新增burst、多ID、并发load、中断、全局复位需扩展模型和负测。
5. 接入后重新跑BUS-01/03/06，之后才有CPU实现证据。未接入时它们仍NOT_RUN；现有精确非法写异常缺口保持开放。
